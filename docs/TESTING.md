## Що саме перевіряють тести

**Ядро (C++):**

* розбір JSON: кирилиця, екранування, сурогатні пари UTF-16, відхилення некоректного вводу;
* формула індексу на прикладі, порахованому вручну: 100 · (0,30·0,5 + 0,25·0,6 + 0,30·0,5) = 45;
* множник координатора хабу та обмеження ex post для важливих суб'єктів;
* фіксація пропущеного звіту рівно один раз і ескалація до Р1;
* зараження через спільного постачальника між різними хабами і обов'язкова перевірка людиною для тимчасових заходів;
* повний життєвий цикл інциденту: реєстрація, три етапи звіту, повторне й некоректне подання, закриття, аудит, запізніла подія;
* робочі дні: п'ятниця + 1 = понеділок;
* відтворюваність моделювання каскадів і ранжування великого постачальника вище за малого.

**Python:**

* замкнений цикл на 30-денному сценарії породжує всі ключові типи рішень;
* інцидент без жодного звіту дає порушення строку;
* калібрування на синтетичних даних відновлює приховану модель: вага загрози менша за 0,08, AUC зростає;
* REST API: реєстрація інциденту, каскад термінових процедур, відмова (`422`) у затвердженні акта без посадової особи, відхилення недопустимої події (`400`).

## Як відтворити

```bash
make test       # усі тести
make lint       # стиль і статичний аналіз
make sanitize   # ASan, UBSan, TSan
make coverage   # покриття
```

На кожен push до репозиторію ті самі перевірки автоматично запускає GitHub Actions на Ubuntu і macOS (`.github/workflows/ci.yml`).
